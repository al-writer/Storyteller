# Правила работы в репозитории

## Ветки

Имя ветки — `<тип>/<кратко-через-дефис>`, латиницей в нижнем регистре, 2–5 слов о сути
изменения: `feat/phrase-story`, `fix/flaky-cookie-test`, `chore/code-review-issue-template`.
Если работа закрывает issue, номер можно поставить в начало описания: `fix/19-unsaved-story`.

Тип — тот же, что в префиксе сообщения коммита (Conventional Commits):

| Тип        | Для чего                                         |
|------------|--------------------------------------------------|
| `feat`     | новая возможность                                |
| `fix`      | исправление ошибки                               |
| `refactor` | переделка кода без изменения поведения           |
| `perf`     | производительность                               |
| `test`     | только тесты                                     |
| `docs`     | только документация                              |
| `build`    | сборка, зависимости, деплой                      |
| `ci`       | GitHub Actions                                   |
| `chore`    | прочее обслуживание (шаблоны, конфиги, метки)    |

Автоматические имена вида `cld/<случайные-слова>` не используем: если сессия выдала такую
ветку, до первого пуша переименуйте её по правилу выше.

## Код-ревью

- Замечания к открытому PR — комментариями в самом PR.
- Невлитые в PR исправления и находки в уже влитом коде — отдельный issue на каждое
  замечание по шаблону `.github/ISSUE_TEMPLATE/code-review.md` (метка `code-review`).
- Исправление закрывает issue коммитом или PR с `Fixes #N`.
